# EIP-712 order format

This document defines the signed order used by the frontend, backend, and
`LimitOrderExecutor`. Field order and integer units are part of the signature
contract.

## 1. Units

Token amounts and prices use 18-decimal integer math.

- Player-token prices are denominated in the player's country token.
- Country-token prices are denominated in PITCH.
- `amountIn`, `targetPrice`, and the calculated output floor are integer
  values, not floating-point display values.

## 2. Domain

```text
name:              PitchTerminal LimitOrders
version:           1
chainId:           deployment chain ID
verifyingContract: LimitOrderExecutor address
```

Changing the chain or executor address changes the digest and prevents replay
against another deployment.

## 3. Order

### 3.1 Canonical type

```solidity
Order(
  address owner,
  address token,
  address quoteToken,
  uint8 venue,
  uint8 side,
  uint256 targetPrice,
  uint256 amountIn,
  uint256 slippageBps,
  uint256 expiry,
  uint256 nonce
)
```

The canonical type string has no whitespace:

```text
Order(address owner,address token,address quoteToken,uint8 venue,uint8 side,uint256 targetPrice,uint256 amountIn,uint256 slippageBps,uint256 expiry,uint256 nonce)
```

### 3.2 Hashing

The struct hash is `keccak256(abi.encode(ORDER_TYPEHASH, ...fields))`. The
signed digest is:

```text
keccak256(0x1901 || DOMAIN_SEPARATOR || structHash)
```

The executor exposes `hashOrder` and `digest` for cross-checking.

### 3.3 Fields

| Field | Meaning |
|---|---|
| `owner` | Signer, source of input funds, and output recipient |
| `token` | Player or country token being traded |
| `quoteToken` | Country token for player markets; PITCH for country markets |
| `venue` | `0` player, `1` country |
| `side` | `0` limit buy, `1` take profit |
| `targetPrice` | Trigger price in quote-token units |
| `amountIn` | Maximum input amount pulled from the owner |
| `slippageBps` | Signed slippage bound, capped at 1,000 |
| `expiry` | Unix time; `0` means no deadline |
| `nonce` | Owner-scoped cancellation and replay key |

### 3.4 Frontend representation

The viem type declaration must use the same field names, order, and Solidity
types. Reordering fields or changing a type produces a different signature.

## 4. Price source

`venue` selects one of two immutable hooks:

- player venue to `PLAYER_HOOK`;
- country venue to `COUNTRY_HOOK`.

The executor reads `currentPrice(token)` once during execution. A zero price
is rejected.

## 5. Trigger and minimum output

### 5.1 Trigger

- Limit buy: execute when `livePrice <= targetPrice`.
- Take profit: execute when `livePrice >= targetPrice`.

### 5.2 Minimum output

The output floor uses signed values rather than live price.

```text
discount = fixed protocol fee (500 bps) + slippageBps

limit buy:
  ideal = amountIn * 1e18 / targetPrice

take profit:
  ideal = amountIn * targetPrice / 1e18

minOut = ideal * (10,000 - discount) / 10,000
```

The executor compares the actual post-swap balance with `minOut`.

## 6. Execution flow

1. Validate amount, price, addresses, venue, side, slippage, and expiry.
2. Require PITCH as the quote token for a country-market order.
3. Reject a used nonce.
4. Verify the EIP-712 signature for `owner`.
5. Read the venue hook and check the trigger.
6. Mark the nonce used.
7. Pull `amountIn` from the owner.
8. Approve and call the immutable venue router.
9. Reset router approval to zero.
10. Check the actual output and send it to the owner.

For a player venue, quote-token compatibility is enforced by the fixed router
rather than by a separate executor registry.

## 7. Cross-check

A representative order should produce the same digest in:

- viem `hashTypedData`;
- backend EIP-712 helpers;
- `LimitOrderExecutor.digest`.

The contract tests include this comparison. A mismatch blocks order creation
or execution rather than being normalized after signing.
