## 1. Единицы и precision

Все ERC20 в системе — **18 decimals**. Это включает PITCH, токены стран и токены
игроков.

**Цена** в кривой выражается как «сколько единиц quote-токена за 1 единицу
base-токена» — то же самое, что `quoteBuy(token, 10**18)` (один токен на входе ⇒
сколько выходит quote). Хранится как `uint256` wei-quote-за-1-целый-base.

- Для **player-токена**: quote = country-token, base = player-token. Цена в country-wei
  за 1 player-token (1e18 единиц).
- Для **country-токена**: quote = PITCH, base = country-token. Цена в PITCH-wei за
  1 country-token.

Пример: цена country-токена `12.5 PITCH` за 1 = `12_500_000_000_000_000_000`
(=`12.5 * 1e18`).

**В `targetPrice` лимит-ордера** используется именно эта единица. Это в точности тот
же скаляр, который возвращает `hook.currentPrice(token)`.

## 2. EIP-712 Domain

```
EIP712Domain {
  string  name;
  string  version;
  uint256 chainId;
  address verifyingContract;
}
```

Константы:
- `name` = `"PitchTerminal LimitOrders"`
- `version` = `"1"`
- `chainId` = `8453` (Base)
- `verifyingContract` = адрес `LimitOrderExecutor` (immutable после деплоя)

`domainSeparator = keccak256(abi.encode(EIP712_DOMAIN_TYPEHASH, keccak256(name),
keccak256(version), chainId, verifyingContract))`.

`EIP712_DOMAIN_TYPEHASH` = `keccak256("EIP712Domain(string name,string version,uint256
chainId,address verifyingContract)")`.

При смене `chainId` или адреса контракта подписи становятся невалидными — это
ожидаемо (replay protection между сетями и инстансами).

## 3. EIP-712 Order struct

### 3.1 Solidity / canonical type

```
Order(address owner,address token,address quoteToken,uint8 venue,uint8 side,uint256 targetPrice,uint256 amountIn,uint256 slippageBps,uint256 expiry,uint256 nonce)
```

**typeHash:**
```
ORDER_TYPEHASH = keccak256(
  "Order(address owner,address token,address quoteToken,uint8 venue,uint8 side,uint256 targetPrice,uint256 amountIn,uint256 slippageBps,uint256 expiry,uint256 nonce)"
);
```

Никаких пробелов внутри строки кроме одного между типом и именем поля.

### 3.2 Hashing

```solidity
function _hashOrder(Order calldata o) internal pure returns (bytes32) {
    return keccak256(abi.encode(
        ORDER_TYPEHASH,
        o.owner,
        o.token,
        o.quoteToken,
        uint256(o.venue),    // uint8 кастуется до uint256 при abi.encode (32 байта)
        uint256(o.side),
        o.targetPrice,
        o.amountIn,
        o.slippageBps,
        o.expiry,
        o.nonce
    ));
}

function _digest(Order calldata o) internal view returns (bytes32) {
    return keccak256(abi.encodePacked("\x19\x01", _domainSeparator(), _hashOrder(o)));
}
```

### 3.3 Поля

| Поле | Тип | Семантика | Диапазон |
|---|---|---|---|
| `owner` | `address` | Подписант ордера; адрес кошелька пользователя | non-zero |
| `token` | `address` | Торгуемый токен (игрока или страны) | non-zero, из реестра |
| `quoteToken` | `address` | Quote-валюта пары: для player-venue — country-токен этого игрока; для country-venue — PITCH | non-zero |
| `venue` | `uint8` | 0 = player, 1 = country | {0, 1} |
| `side` | `uint8` | 0 = limit-buy, 1 = take-profit | {0, 1} |
| `targetPrice` | `uint256` | Целевая цена (см. §1, в quote-wei за 1 целый base) | > 0 |
| `amountIn` | `uint256` | Сумма входного токена. Для limit-buy: quoteToken; для take-profit: token | > 0 |
| `slippageBps` | `uint256` | Допуск проскальзывания, базисные пункты (1bp = 0.01%) | ≤ `MAX_SLIPPAGE_BPS` (=1000, т.е. 10%) |
| `expiry` | `uint256` | Unix-секунды; **0 = без срока** | 0 или > now |
| `nonce` | `uint256` | Уникальный на пару `(owner, contract)`; рекомендуется криптослучайный 256-битный | произвольно |

**Почему `quoteToken` подписан, а не выводится on-chain:**
`hook.getBaseCurrency(token)` существует в pitchwc-контракте, но известен **багом**:
для части токенов реверитит. Корректное соответствие player → country и country → PITCH
лежит у нас в seed-данных (`tokens.country_address`), не on-chain. Делать executor
зависимым от внеконтрактного источника опасно. Решение: фронт резолвит `quoteToken`
из seed, пользователь подписывает явно. **Если пользователь подпишет неверный
quoteToken** — контракт сделает `transferFrom` подписанного токена, попытается
свопнуть через router, тот реверитнет (несовместимая пара), вся tx откатится:
средства пользователя в безопасности, средства других пользователей не затронуты.
Это self-DoS, не уязвимость.

### 3.4 viem (frontend)

```ts
import { hashTypedData, signTypedData } from 'viem/actions';

const types = {
  Order: [
    { name: 'owner', type: 'address' },
    { name: 'token', type: 'address' },
    { name: 'quoteToken', type: 'address' },
    { name: 'venue', type: 'uint8' },
    { name: 'side', type: 'uint8' },
    { name: 'targetPrice', type: 'uint256' },
    { name: 'amountIn', type: 'uint256' },
    { name: 'slippageBps', type: 'uint256' },
    { name: 'expiry', type: 'uint256' },
    { name: 'nonce', type: 'uint256' },
  ],
} as const;

const domain = {
  name: 'PitchTerminal LimitOrders',
  version: '1',
  chainId: 8453,
  verifyingContract: limitOrderExecutorAddress,
} as const;

const signature = await signTypedData(walletClient, {
  account: ownerAddress,
  domain,
  types,
  primaryType: 'Order',
  message: order,
});
```

**Важно:** массив полей в `types.Order` должен идти в **том же порядке**, что и
в `ORDER_TYPEHASH`. Любая перестановка изменит typeHash и подпись не сойдётся
с контрактом.

## 4. Чтение цены у хука

Оба хука (Player Hook и Country Hook) экспонируют `currentPrice(address token) view
returns (uint256)`:

```solidity
interface IHook {
    function currentPrice(address token) external view returns (uint256);
    function quoteBuy(address token, uint256 quoteIn) external view returns (uint256 baseOut);
    function quoteSell(address token, uint256 baseIn) external view returns (uint256 quoteOut);
}
```

Семантика (на основе верифицированного контракта pitchwc):
- `currentPrice` возвращает цену **без учёта комиссии** (fee-excluded), в формате
  §1 — quote-wei за 1 целый base. Это та же цена, что рисуется на графике.
- `quoteBuy(token, quoteIn)` — сколько base-токенов будет получено, если потратить
  `quoteIn` wei quote-токена (с учётом 5% комиссии).
- `quoteSell(token, baseIn)` — сколько quote-токенов получит продавец после уплаты
  комиссии за продажу `baseIn` wei base-токена.

### 4.1 Резолюция venue → hook

В `LimitOrderExecutor` четыре immutable-адреса:

```solidity
IHook   immutable public PLAYER_HOOK;
IHook   immutable public COUNTRY_HOOK;
IRouter immutable public PLAYER_ROUTER;
IRouter immutable public COUNTRY_ROUTER;

function _hookFor(uint8 venue) internal view returns (IHook) {
    if (venue == 0) return PLAYER_HOOK;
    if (venue == 1) return COUNTRY_HOOK;
    revert InvalidVenue();
}

function _routerFor(uint8 venue) internal view returns (IRouter) {
    if (venue == 0) return PLAYER_ROUTER;
    if (venue == 1) return COUNTRY_ROUTER;
    revert InvalidVenue();
}
```

Owner-задаваемого `mapping(token => router)` нет — это закрывает вектор «owner
ставит вредоносный роутер». venue подписан пользователем в ордере, маппинг venue →
router immutable в constructor → ничто не подменится.

## 5. Проверка условия и `minOut`

### 5.1 Условие срабатывания

```solidity
uint256 price = _hookFor(o.venue).currentPrice(o.token);

if (o.side == 0 /* limit-buy */) {
    require(price <= o.targetPrice, PriceConditionNotMet());
} else /* take-profit */ {
    require(price >= o.targetPrice, PriceConditionNotMet());
}
```

Хороший вопрос — что считать «ценой» для take-profit: рыночную или эффективную (с
комиссией)? Решение: **используем рыночную цену кривой (`currentPrice`)**. Это
единственное, что пользователь видит на графике и в UI, и единственное, что не
зависит от направления сделки. Учёт 5% комиссии — через `minOut` и `slippageBps`
(см. ниже): пользователь сознательно даёт допуск, перекрывающий ожидаемую комиссию.

### 5.2 Вычисление `minOut`

**Ключевая защита от sandwich:** `minOut` считается **только из подписанных полей**
(`targetPrice`, `amountIn`, `slippageBps`), **не из текущей рыночной цены**. Манипулятор,
шевельнувший цену в момент исполнения, не может уменьшить `minOut`.

```solidity
// 1e18 fixed-point; precision 18 decimals.
uint256 internal constant ONE = 1e18;
uint256 internal constant BPS_DENOM = 10_000;
uint256 internal constant FEE_BPS = 500;   // 5% комиссия pitchwc

function _minOut(Order calldata o) internal pure returns (uint256) {
    if (o.side == 0 /* limit-buy */) {
        // Покупаем base за quote. Идеальный выход (без комиссии и без проскальзывания):
        //   baseOut_ideal = amountIn * ONE / targetPrice
        // Учитываем 5% fee + slippageBps как одну скидку:
        uint256 discount = FEE_BPS + o.slippageBps;
        require(discount < BPS_DENOM, "slippage cap");
        uint256 baseIdeal = (o.amountIn * ONE) / o.targetPrice;
        return baseIdeal * (BPS_DENOM - discount) / BPS_DENOM;
    } else /* take-profit */ {
        // Продаём base за quote.
        //   quoteOut_ideal = amountIn * targetPrice / ONE
        uint256 discount = FEE_BPS + o.slippageBps;
        require(discount < BPS_DENOM, "slippage cap");
        uint256 quoteIdeal = (o.amountIn * o.targetPrice) / ONE;
        return quoteIdeal * (BPS_DENOM - discount) / BPS_DENOM;
    }
}
```

**Почему складываем `FEE_BPS + slippageBps`:** пользователь в UI вводит slippage как
«сколько хуже моей цели я готов получить» — и эта точка отсчёта уже не учитывает
5% протокольный сбор. Складывая, мы гарантируем, что подписанный slippage отражает
реальный допуск над **очищенной от комиссии** ценой. В UI это подсветим явной
строкой: «получишь ≈Y; включает 5% комиссию pitchwc + ваш slippage».

**`FEE_BPS = 500`** хардкод в контракте: значение pitchwc-протокола; смена потребует
ре-деплоя. Если pitchwc когда-нибудь сменит fee — это разрушит наши ордера, что
ожидаемо (требуется ре-деплой со значением, чтобы старые ордера не исполнились
с неверным расчётом).

## 6. Reference flow `execute()`

Псевдо-Solidity для аудиторской проверки:

```solidity
function execute(Order calldata o, bytes calldata sig)
    external
    nonReentrant
    whenNotPaused
{
    // ---- Checks ----
    // 1. Bounds & validity (cheap, fail fast)
    require(o.amountIn > 0, "amountIn");
    require(o.venue <= 1, "venue");
    require(o.side  <= 1, "side");
    require(o.slippageBps <= MAX_SLIPPAGE_BPS, "slippage cap");
    require(o.expiry == 0 || block.timestamp <= o.expiry, "expired");
    require(o.targetPrice > 0, "target");
    require(o.token != address(0) && o.quoteToken != address(0), "zero addr");
    require(!_nonces[o.owner][o.nonce], "nonce used");
    // venue=country → quoteToken должен быть PITCH (см. §6.1)
    if (o.venue == 1) require(o.quoteToken == PITCH, "bad quote");

    // 2. Signature
    bytes32 digest = _digest(o);
    require(
        SignatureChecker.isValidSignatureNow(o.owner, digest, sig),
        "bad sig"
    );

    // 3. Price condition
    uint256 price = _hookFor(o.venue).currentPrice(o.token);
    if (o.side == 0) require(price <= o.targetPrice, "price");
    else             require(price >= o.targetPrice, "price");

    // ---- Effects ----
    _nonces[o.owner][o.nonce] = true;

    // ---- Interactions ----
    (address inToken, address outToken) = _ioTokens(o);

    IERC20(inToken).safeTransferFrom(o.owner, address(this), o.amountIn);
    IRouter router = _routerFor(o.venue);
    IERC20(inToken).forceApprove(address(router), o.amountIn);

    uint256 minOut = _minOut(o);
    if (o.side == 0) {
        router.buy(o.token, o.amountIn, minOut);
    } else {
        router.sell(o.token, o.amountIn, minOut);
    }

    // Reset residual allowance — defensive против багов router'а, оставляющего
    // часть allowance неиспользованной. Бесплатно для нас (one SSTORE на 0),
    // снимает класс будущих атак, если router окажется уязвимым.
    IERC20(inToken).forceApprove(address(router), 0);

    // Forward the *entire* outToken balance — no dust.
    uint256 outBal = IERC20(outToken).balanceOf(address(this));
    require(outBal >= minOut, "minOut not met");
    IERC20(outToken).safeTransfer(o.owner, outBal);

    emit OrderExecuted(o.owner, o.nonce, o.token, o.amountIn, outBal);
}

function _ioTokens(Order calldata o)
    internal
    pure
    returns (address inToken, address outToken)
{
    // limit-buy: spend quoteToken, receive token.
    // take-profit: spend token, receive quoteToken.
    if (o.side == 0) { inToken = o.quoteToken; outToken = o.token; }
    else             { inToken = o.token;       outToken = o.quoteToken; }
}
```

### 6.1 Sanity-проверка `quoteToken` против venue

Контракт **не** обращается к внешним источникам для проверки корректности
пары `(token, quoteToken)`. Это самозащита через router:

- Для player-venue: контракт вызывает `PLAYER_ROUTER.buy(o.token, o.amountIn, minOut)`.
  Router pitchwc ожидает строго определённый country-токен на входе (свой внутренний
  маппинг). Если пользователь подписал не тот `quoteToken` — `transferFrom` сработает,
  но `forceApprove` будет дан не на тот токен, а сам router сделает `transferFrom`
  именно того токена, который ему нужен → у executor'а его нет → revert.
- Для country-venue: `quoteToken` обязан быть PITCH. Контракт `LimitOrderExecutor`
  знает `PITCH` как `immutable` (constructor-параметр) — **здесь добавляем явную
  проверку**: `if (o.venue == 1) require(o.quoteToken == PITCH, "bad quote")`.
  Стоит дёшево и закрывает основной случай.

Player-venue же оставляем без on-chain проверки: единственный путь — попытаться
своп через router и положиться на его revert.

## 7. Кросс-проверка viem ↔ Solidity

Перед тем как считать первое исполнение успешным, **обязательно** провести следующий
ритуал в репликабельной форме (Foundry test + viem-скрипт):

1. Зафиксировать конкретный `Order` (все поля захардкожены).
2. Получить `digest`:
   - В Foundry: `bytes32 d = executor._digest(order)` (тестовый wrapper).
   - В viem: `hashTypedData({ domain, types, primaryType: 'Order', message: order })`.
3. Убедиться, что они **побитово совпадают**.
4. Подписать тестовым ключом в обеих средах → подписи идентичны.
5. Передать подпись + ордер в `execute()` (Foundry-fork-test на Base) → проходит до
   шага проверки цены (после — упрётся в реальный Hook).

Этот ритуал ловит расхождения в порядке полей, encoding'е `uint8 → uint256`, и
domain separator'е до того, как они попадут в продакшен.
